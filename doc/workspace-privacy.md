# 工作区工具与应用私有存储

应用启动通过 `configureWorkspacePrivateDirectory()` 显式注册 development / release 的配置目录。接口接受单一路径、只读路径数组或 `null`；不改变默认聊天 cwd，不迁移数据，也不创建 Git 仓库。

注册的目录作为私有存储边界。根容器可以列出，但其中只有用户生成的 `artifacts/` 与 `generated-images/` 可以作为工作区文件访问。其他已知或新增内部项默认拒绝，包括设置、数据库及侧文件、Cursor 凭据、attachments、屏幕捕获 / 控制 / 状态 / 安装 helper、tool-results、agent-tasks、checkpoints、worktrees 和 hooks 配置。

`view`、`fileStat`、写入、二进制写入与目录列表共用这一策略；编辑通过同一读取 / 写入接口执行。检查覆盖请求路径、实际路径及不存在目标的最近实际祖先，不能通过目录别名或 symlink 引用另一聊天的未发送捕获和旧工具结果。目录列表隐藏内部项。其他工程中的普通 `settings.json` 不因文件名而被禁止。

搜索不以“结果出来以后再过滤”为保护手段：在配置目录 cwd 下，只把两个公开输出目录传给 ripgrep；在 home、文件系统根等更广范围中，实际 `--glob` 排除整个已注册配置目录。调用者的 glob 位于保护规则之前，不能覆盖这些排除。普通密钥路径的现有规则也用于实际搜索。公开输出仍可从其所属默认 cwd 或明确的公开子树搜索，广域搜索不会遍历应用配置目录。

这一边界保护非审批的文件工具，不是进程沙箱。Bash 的显式审批、用户主动发送捕获以及按 session 验证工具结果引用，分别由各自入口负责。未注册的其他软件目录，以及应用配置目录以外的日志位置，不应被称为已经覆盖。

回归测试使用临时目录和 canary 文本，覆盖跨聊天捕获 / 旧工具 refs、设置与控制文件、别名写入、列表隐藏、真实 ripgrep 排除、调用者 glob、宽根目录、两个明确配置根，以及其他工程正常设置与用户输出。
